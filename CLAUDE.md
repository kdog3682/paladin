# Paladin

- Anything about `webrun` (serving an app, what's running, which app/url/pid, stopping it, probing a page): run `webrun --help` or `webrun --status` first. `--status` prints the served app, url, mode, pid, uptime and new vite errors; don't go hunting through `ps`/`ss`/`.webrun` dirs.
- Checking what a page does in a real browser (any web project, not just paladin): `webrun` with action flags. Loads the page in headless Chrome, optionally drives it (`--keypress alt+f --expect '[role=dialog]'`, `--click`, `--type`, `--text <sel>`, `--style <sel>`, `--reload <ms>` (wait for the page to reload itself while another terminal swaps the app), `--eval`, `--screenshot`, chained in order; `--preview` also prints a compact outline of the page), and always reports console errors/warnings, failed requests and font loading; exits 1 if an action fails. No target probes the running server; `webrun path/to/App.tsx --click ...` serves it first (no browser tab unless `--open`); `webrun http://... --text body` probes any url, e.g. a project's own dev server. Don't write one-off puppeteer scripts or synthetic `dispatchEvent` calls. Source: `packages/webrun/src/cli.ts` (probe in `src/probe`); if the command is missing, `ln -s $PWD/packages/webrun/src/cli.ts ~/.local/bin/webrun`.
- Codemods (running/testing transforms, corpus fixtures): see `packages/codemod/README.md`.
- `packages/api2` (scaffold, CodeRunner, post-processors) is heavily edited. Before changing it, read `packages/api2/docs/scaffold.md` (pipeline) and, for the runner, `packages/api2/docs/runner.md`.
