# Paladin

- Checking what a page does in a real browser (any web project, not just paladin): `web-probe --help`. Loads the page in headless Chrome, optionally drives it (`--keypress alt+f --expect '[role=dialog]'`, `--click`, `--type`, `--text <sel>`, `--reload <ms>` (wait for the page to reload itself while another terminal swaps the app), `--eval`, `--screenshot`, chained in order; `--preview` also prints a compact outline of the page), and always reports console errors/warnings, failed requests and font loading; exits 1 if an action fails. The app must already be served (`webrun`, or the project's own dev server; pass its url). Don't write one-off puppeteer scripts or synthetic `dispatchEvent` calls. Source: `packages/webrun/src/probe`; if the command is missing, `ln -s $PWD/packages/webrun/src/probe/cli.ts ~/.local/bin/web-probe`.
- Codemods (running/testing transforms, corpus fixtures): see `packages/codemod/README.md`.
- `packages/api2` (scaffold, CodeRunner, post-processors) is heavily edited. Before changing it, read `packages/api2/docs/scaffold.md` (pipeline) and, for the runner, `packages/api2/docs/runner.md`.
